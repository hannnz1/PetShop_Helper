## 2026-09-27 — Task 2 模型窗口预算与中文校准

- 用户关键原话/约束：按模型窗口倒推预算；演示配置目标历史约 5650（第一层约 3954、第二层 1695）；系统、证据、摘要、输出和 ReAct 峰值均计入；中文校准统一；保留旧 `TOKEN_BUDGET` 显式兼容。
- 关键产出：`FixedCosts.measure` 以 LangChain 的 `count_tokens_approximately(chars_per_token=...)` 计量稳定文本，`derive_budget` 对可用窗口与二十轮稳态目标取较小值并按 70/30 分层，`validate_context_budget` 拒绝一轮必要内容溢出。演示测试测得 5650 / 3955 / 1695；默认二十个短轮次完全落在第一层。
- 拒绝/纠偏：`.env.example` 把旧 `TOKEN_BUDGET` 改成注释示例；只有显式设置才成为硬上限，不能绕过一轮自检。预算和原有 `estimate_tokens` 共用 `CJK_CHARS_PER_TOKEN`，没有把演示数字硬编码进实现。
- 翻车与返工：RED 阶段测试因新模块缺失而失败；初次 GREEN 中固定开销敏感性测试窗口太宽，被二十轮目标截住，改用受窗口约束的配置后通过。定向预算、内存、配置共 47 项通过；启动调用与上游真实 usage 对照留给后续集成/上游恢复。

## 2026-09-27 — Task 2 复审修正：ReAct 峰值

- 用户关键原话/约束：复审要求当前轮峰值覆盖先前 assistant 工具调用载荷与工具结果的累计，而不只计用户输入和工具结果。
- 关键产出：峰值改为最大用户输入加 `(MAX_AGENT_STEPS - 1) × (MAX_OUTPUT_TOKENS + TOOL_RESULT_MAX_TOKENS)`；后一项分别给每个已完成工具步的 assistant 输出（包含工具调用参数）和该步工具结果总量留额。演示固定开销夹具调整为系统工具 650、证据 800、摘要 250、安全 250，总计 1950；演示 18000 窗口仍导出 5650 / 3955 / 1695。
- 拒绝/纠偏：原 5600 当前峰值漏计 assistant 生成；修正后为 8400，不把上一步模型输出当作只占最终输出的一份。
- 翻车与返工：新增独立 RED 测试明确三次已完成工具交换的积累，旧实现 2300 对预期 3000，随后修复；定向预算、内存、配置 48 项通过。运行时按步限制工具结果总量仍待图集成。
