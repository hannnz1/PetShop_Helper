# 第 9 章第一部分设计：本地可观测性与评估趋势

日期：2026-09-27。状态：待用户审阅书面 spec。前置提交：第 8 章 `80c67ae`。

## 目的与边界

用户希望依照开发手册完成第 1–10 章，并已批准第 9 章第一部分采用本机 Docker 自托管 Langfuse。客服的一次 Graph 对话应能按调用链定位模型、检索和工具步骤；运营能看见每类意图消耗的 token，以及同一份 RAG 评估集随时间变化的分数。本设计只覆盖可观测性、成本统计和定期评估。低置信度问题的标准化、查重、人工审核与知识回流是第 9 章第二部分，另写 spec/plan；第 10 章分类模型不提前实现。

第 8 章真实 glm-5.2 五题验收仍为 `pending_upstream`。本章不能用离线或假模型运行结果冒充真实服务验收。第 4 章的 300 题四策略生成亦受模型余额限制，其历史部分结果保持原状态。

## 已有基础

- 主入口是 `GraphRuntime` 的 `ainvoke_turn`、`prepare_stream_turn` 和 `prepare_resume_turn`；LangGraph 已编译，Graph 维护会话和业务节点。
- 第 8 章工具执行引擎已有 `tool_audit_logs`，可从会话 ID 对照工具结果，不另造第二套工具审计。
- 第 4 章有标注集、检索/生成评估脚本以及 `low_confidence_questions` 表；本部分复用评估输入，不改问题池语义。
- 用户选择本机 Docker 自托管，不授权把 trace 中的对话与检索内容发送到 Langfuse Cloud。

## 方案选择

单纯挂回调只方便看一条 trace，无法形成可验证的意图成本和评估趋势；全部自建 trace 存储则重复 Langfuse。采用分工：Langfuse 保存本机调用链明细；MySQL 保存最小化的 token 统计与评估运行摘要。敏感正文不进入统计表。Langfuse 使用其官方自托管 Docker Compose，放在独立项目与命名卷，配置文件只留示例值，不纳入真实密钥；不能更改或清空现有 MySQL、Milvus、MCP 容器及其卷。启动前检查 Docker 可用资源。关闭观测功能时不要求 Langfuse 运行。

## 调用链

在每次 Graph 调用和流式调用的运行配置中附加当前 Langfuse Python SDK 的 LangChain `CallbackHandler`。会话 ID 和本轮请求 ID 用于关联 trace、`tool_audit_logs` 与应用日志；用户标识作稳定假名，不作为明文标签。trace 按 Graph 节点保留模型、工具、检索的先后和时长，并在界面中可定位失败步骤。SDK 初始化和回调异常不得让正常客服请求失败；观测失败记应用日志，不向 SSE 输出内部细节。只允许把 `LANGFUSE_BASE_URL` 指向本机回环地址或明确配置的自托管内网地址，Cloud 地址需另行授权。

Langfuse 可采集输入和输出正文，部署界面必须限制在本机，访问凭据仅在 `.env` 或本机密钥存储中；应用禁止把 API 密钥、数据库 DSN 和内部授权头写入 trace。禁用开关及缺失凭据时直接走现有对话路径，不创建远程客户端。具体 SDK 接入点、回调异常隔离和是否需要应用级掩码以实装版本及 Context7 官方文档验收。

## 按意图的 token 账

模型调用结束时从模型返回的实际 usage 元数据提取输入和输出 token。用唯一模型运行 ID 防止流式最终块或重试重复记账，保存 `conversation_id`、本轮 ID、意图、模型名、token 数、时间及是否估算到新的轻量表；不存 prompt、回复或工具参数。意图在路由节点最终确定后归属本轮所有模型调用；若某次模型调用早于意图识别，结算时仍归入该轮最终意图，未确定则记 `unknown`。没有 usage 元数据时记 `unavailable`，不填零或凭字符数冒充真实用量。按天、意图和模型汇总次数与输入/输出 token，提供 CLI 报表及只读 API；货币成本需有明确价目表才计算，否则仅展示 token。

## 周期评估与趋势

新建可重跑的评估包装命令，固定读取第 4 章标注集并调用已有检索与生成评估实现，不改指标定义。每次运行记录输入集 hash、Git 版本、模型/策略、开始结束时间、各指标的分子分母或样本数、`passed`/`failed`/`pending_upstream` 状态与报告路径。原始报告保存在本机忽略目录，MySQL 仅存摘要；相同 run ID 幂等，历史运行不可覆盖。没有 Milvus、SiliconFlow 或 glm-5.2 额度时，依赖它们的指标显示不可用和原因，不能沿用旧分数填充。趋势接口按时间返回同一数据集和策略的可比运行；分母或数据集 hash 不同必须显式标注，不直接画为同一条可比较曲线。Windows 下提供可由任务计划程序调用的单次运行命令和示例调度说明，不在应用请求路径内跑批量评估。

## 验收标准

1. 本地 Langfuse 正常时，一次隔离的假模型 Graph 对话出现可关联的调用树；关闭 Langfuse 或故意断开时，对话与 SSE 仍完成，敏感密钥不进入 trace。
2. 固定 usage 元数据的多轮样例按意图、模型和日期汇总正确；重复回调不重复计数，缺 usage 显示不可用。
3. 同一评估集两次离线样例运行形成可读趋势；数据集变化不混算，缺服务的指标保留 `pending_upstream`。
4. 真实本机 Docker Langfuse 启动和 trace 入库、实际模型 token/cost 与完整 RAG 回归分别记录真实结果；若余额或依赖不满足，验收报告逐项写明，不宣称 PASS。
