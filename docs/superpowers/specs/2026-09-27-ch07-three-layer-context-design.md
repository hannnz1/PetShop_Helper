# Ch07 设计：单会话三层上下文与会话切换

状态：待书面评审。依据：`C:\Users\Administrator\Documents\PetShop_Helper开发文档\7\实战演练：动手实现上下文管理.md` 的章首需求，以及 2026-09-27 用户确认“按此设计，写第 7 章 spec”。

## 目标与边界

同一通客服会话持续二十轮以上时，近期内容原样保留、较早内容按规则缩短、最早内容异步写成只追加的分段摘要。模型输入始终有明确预算，用户可在页面切回旧会话并看到完整原文。此章不做跨会话记忆、用户画像或语义检索历史。上游 glm-5.2 余额不足期间只完成离线实现与验收，真实摘要生成和多轮模型验收保留为待验证，绝不将离线结果称作真实模型通过。

本章属于既有 LangGraph、MySQL、SSE 和聊天页之间的架构改动。保留第 5、6 章的意图分流、工具循环、订单中断与人工确认退款语义。

## 现状与设计取舍

当前 `ConversationState.messages` 已用 `add_messages`，SQLite checkpoint 保留完整 Graph 消息；`_fit_messages` 仅在固定 `TOKEN_BUDGET=2000` 内按最近完整轮次裁剪。MySQL `messages` 保存用户、工具结果、客服消息，页面只持有一个 localStorage 会话 ID。章内附带的旧版 spec/验收记录采用“30 条触发、反复改写一段摘要”的两层方案；它与章首最新三层需求及本次确认冲突。本 spec 以章首需求为准：按 token 用量触发、两锚点划层、旧摘要永不重写。

不把摘要混入 checkpoint 的 `messages`，也不删除其中的旧原文。MySQL 的 `conversations` 和 `messages` 是会话索引与原文展示/audit；checkpoint 是 Graph 运行态；`conversation_summaries` 是模型可用的早期记忆。三者各有用途，通过会话 ID 和 MySQL 消息 ID 关联。自 Ch07 起新写入的 MySQL `messages` 只含用户和客服可见原文，工具结果继续留在 checkpoint/运行日志，不再新增 `role=tool` 审计行；旧工具行保留，侧栏回载时过滤。第 6 章 audit marker 仍指向该轮最后一条 MySQL 客服消息，并验证旧记录及 checkpoint 不分叉。

## 数据与边界

沿用章首给出的 SQL 形状：`conversations` 加 `summary TEXT`、`summary_upto_msg_id BIGINT`、`layer1_from_msg_id BIGINT`；新增 `conversation_summaries(id, conversation_id, seq, from_msg_id, upto_msg_id, content, created_at)`，`(conversation_id, seq)` 唯一。`summary` 仅是最近分段内容的可重建投影，不是摘要真源；其长度有上限，完整分段保留在新表。

ID 语义为 `id <= summary_upto_msg_id` 属于第三层，`summary_upto_msg_id < id <= layer1_from_msg_id` 属于第二层，`id > layer1_from_msg_id` 属于第一层。空值按尚未推进处理；边界只前进，不搬迁或删改原文。每次降级选择**完整已结束的对话轮次**推进 `layer1_from_msg_id`；当前轮、未完成的订单选择中断以及正在发出的工具调用不入第二层。第二层渲染时用户原话不动，客服答复只保留开头可配置的几十字，大块工具结果仅在 checkpoint 精简视图中变成一行标识。旧 MySQL 工具行不计入消息分层的 token 触发。

第二层超过自身 token 预算时，后台从上一个 `summary_upto_msg_id` 后选择已完成且仍在第二层的连续消息区间，生成**一条新摘要**。在一个 MySQL 事务中锁定会话行，核对旧边界、插入下一序号分段并推进摘要锚点和投影；并发任务只能有一个提交同一区间，失败不推进边界，下轮可重试。每条旧分段永不改写，摘要模型只看到本批原文；旧分段不参与再摘要。相同消息 ID 不得在两段中重复覆盖。摘要只提炼明确商品、订单号或联系方式、诉求与未解决问题，删去寒暄；不得补造事实，长度控制在几十到约二百汉字。无有意义事实则记录 `skip`，但要以可审计方式推进已处理边界，避免每轮反复处理同一批寒暄；可写空事实标记分段，模型拼装时跳过该标记。

摘要调度发生在一轮 SSE 正常结束且 MySQL 原文提交后，不等待摘要模型返回。流中断、数据库写失败或 LangGraph pending 中断均不触发。任务失败留痕且不使已完成回复失败；下轮重新检查预算和缺口。进程关闭时等待有界时间并记录未完成任务；重启后基于锚点发现缺口再触发。多 worker 情况以数据库事务去重，不依赖进程内锁保证唯一性。

## 预算与模型输入

新增明确的窗口、最大输出、最大用户输入、工具结果峰值和期望保留轮数配置；保留兼容旧 `TOKEN_BUDGET` 的迁移说明，避免静默改变旧调用。历史可用额由模型上下文窗口减去固定系统/工具定义、检索证据、摘要、最大输出、安全余量，再减当前 ReAct 工具循环峰值后得到。历史目标额是“期望轮数 × 校准后的单轮稳态 token”；历史预算取目标额与实际可用额的较小值，约 70% 给第一层、30% 给第二层。预算把当前用户输入和该轮尚未完成的工具消息作为不可裁掉的必要内容；一轮都放不下则启动自检明确报警，运行时返回“上下文预算不足”，不能偷偷丢掉系统约束、当前问题或可靠证据。默认设置下二十轮普通对话不应触发降级；演示设置须复现历史约 5650、第一层约 3954、第二层约 1695 token。数字允许因实测系统提示与工具 schema 大小在测试里标明微小差异，不可硬编码为结果。

估算采用 LangChain `count_tokens_approximately`，同时校准中文 `chars_per_token` 与固定开销，记录估算与上游 usage 差异；`trim_messages` 是最后的预算闸，保留完整轮次且不截断用户原话。上游确切 tokenizer 不可得时预算必须保守。摘要段总长也有独立上限，超过时优先保留最近完整段并记录早期段未注入，绝不改写旧段或让输入溢出；这属于可观测的记忆覆盖限制，不声称能无限期记住所有订单。

主力 Agent 每次调用按固定顺序拼装：稳定 system 人设/红线/工具定义，第二层缩短对话，第一层完整原文，当前用户消息及本轮工具交换，然后一条“早期摘要 + 已核验证据”的组合上下文消息。该组合消息位于当前用户消息之后，不单独创建 system 消息；订单本人核验事实也进入此组合消息。每次 ReAct 调用都重新按实际峰值核算，不能只在首步计算。Graph `messages` 原样留在 checkpoint，节点只追加新消息，传给模型的是独立构造的副本。

指代消解和意图识别共享“摘要行 + 预算内滑窗”，每一轮都生成并记录 `history_ctx`，即使最后进入不调用主力 Agent 的闲聊兜底。主力模型每次调用前记录实际 `model_ctx`：完整被注入摘要、逐条窗口消息、条数、token 估算、会话和步骤；后台摘要记录 `trigger/start/done/skip/fail`、边界与耗时。日志写入既有 `log/app.log`，可能含手机号等对话原文，默认只在本机可读并在 README 明示日志保留/清理办法，不在浏览器和 API 回传这些调试日志。

## 会话 API 与页面

`GET /api/conversations?user_id=...` 按最近更新倒序列出该用户会话，含 ID、首问预览、是否有摘要、更新时间；`GET /api/conversations/{id}/messages?user_id=...` 只返回该用户的用户/客服可见原文，按 ID 升序。未知会话或归属不符统一 404，绝不泄漏别人的预览、摘要或消息；参数与现有本地演示 `user_id` 身份模型一致，不引入本章以外的账号认证。旧会话含工具行时过滤工具行。列表分页/上限防止一次读入无界会话；消息接口按页加载并在页面滚动补齐，页面最终能回载完整原文。

聊天侧栏列出会话、预览和摘要标记，选择时停止当前请求或等待其结束，切换 `conversation_id` 后加载历史并继续聊；“新对话”清空当前 ID，不删除旧会话。订单选择 pending 状态必须按会话 ID 保存/恢复，切换不能把旧会话的确认表单带到新会话。侧栏 API 失败静默降级，现有聊天与新建会话仍可用。页面部分遵照用户最初要求采用 Vibe Coding 迭代，不套页面自身的 brainstorm/TDD/code review；后端、数据与上下文逻辑仍走 Superpowers。

## 验收与限制

先以离线假模型/样例对话验证：完整轮次边界、中文预算和默认二十轮无摘要；演示配置下第一层降级→第二层超预算→异步追加摘要；摘要无编造、分段不重写、并发去重/失败重试；模型输入顺序及 `model_ctx`/`history_ctx`；MySQL 历史/旧工具行兼容、Graph audit 与退款中断恢复；会话隔离、分页与侧栏切换/回载，SSE 回复不被摘要阻塞。纯 Prompt 摘要质量用标注样例而非镜像单测评估。
