## 实施前待核对事项

- 上游配置：原稿指定的验收模型与端点，以及 `.env.example` 中的另一组上游示例，均未验证可用性或协议兼容性。先用 Context7 核对接口，再确认实际验收配置；发现固定选型矛盾时询问用户。
- 密钥字段：原稿同时出现 `CHAT_API_KEY` 和 `ANTHROPIC_AUTH_TOKEN`，需要统一映射；本次未创建 `.env`，未请求或使用密钥。
- 配置范围：Spec 写三组 `CHAT_*` / `EMBED_*` / `RERANK_*`，Plan 只在本章引入 `CHAT_*`，其余留后续章节；需要在定稿时统一表述。
- token 预算：Spec 要求保留 system 与完整轮次；Plan 示例仅对历史预算计数，还要明确本轮输入、system 和输出预留的边界，以及超长输入策略。
- 结构化输出：先核验 `with_structured_output` 使用的模式、上游支持情况与本章“不做工具调用”的约束是否一致。
- 执行环境：原稿使用 Bash、make、chmod，当前环境是 Windows PowerShell；正式实施前确定启动与验收命令的运行环境。
- 验证范围：需检查配置单例对测试收集的影响，以及多轮测试是否验证了传给模型的上下文；Prompt 效果以标注样例评估为准。
- 提交署名：原稿指定其他助手的 Co-Authored-By，作为原文保留，不视为本次整理的真实署名；实施提交时应采用真实贡献者信息。

以上是文档一致性待办，不代表框架/API 已经过官方文档核验，也不代表技术方案被更换。
