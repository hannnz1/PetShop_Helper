# Ch04 Context7 official API checks (2026-09-26)

Before changing Milvus/SiliconFlow code, queried Context7 for current official documentation.

- Milvus BM25 schema: [official Milvus docs](https://github.com/milvus-io/milvus-docs/blob/v3.0.x/site/en/aiTools/rag_pipeline.md) show `Function(FunctionType.BM25)`, analyzer-enabled `VARCHAR`, `SPARSE_FLOAT_VECTOR`, dense `AUTOINDEX/COSINE`, and sparse `SPARSE_INVERTED_INDEX/BM25`. [Milvus integration guidance](https://github.com/milvus-io/milvus-docs/blob/v3.0.x/site/en/integrations/langchain/milvus_hybrid_search_retriever.md) states native full-text search needs Standalone/Distributed; Lite does not support it. [Analyzer overview](https://github.com/milvus-io/milvus-docs/blob/v3.0.x/site/en/userGuide/schema/analyzer/analyzer-overview.md) lists `chinese` as a built-in analyzer.
- PyMilvus hybrid API: [official PyMilvus reference](https://github.com/milvus-io/pymilvus/blob/master/_autodocs/api-reference/async-milvus-client.md) and [ranker reference](https://github.com/milvus-io/pymilvus/blob/master/_autodocs/api-reference/rankers.md) define `AnnSearchRequest(data, anns_field, param, limit, filter=...)`, `RRFRanker(k=60)`, and `hybrid_search(collection_name, reqs, ranker, limit, output_fields=...)`. These are documentation examples; the installed `pymilvus==3.0.2` still needs a real Standalone smoke test before implementation proceeds.
- SiliconFlow rerank: [official API reference](https://docs.siliconflow.cn/docs/api/rerank-post) specifies `POST https://api.siliconflow.cn/v1/rerank`, model `BAAI/bge-reranker-v2-m3`, `query`, `documents`, optional `top_n`, and result entries with `index` and `relevance_score`. The copied plan's smoke snippet uses a model ID without `BAAI/`; implementation must use the documented full ID and verify it with the configured account.
- Milvus deployment: [official Docker Compose installation guide](https://github.com/milvus-io/milvus-docs/blob/v3.0.x/site/en/getstarted/run-milvus-gpu/install_standalone-docker-compose-gpu.md) uses Standalone, etcd, and MinIO containers with persistent volumes. The copied plan's POSIX `seq`/`sleep` Make recipe must be adapted for Windows PowerShell and Docker Compose v2.
- Additional PyMilvus checks before the Task 1 smoke: [official `run_analyzer` reference](https://github.com/milvus-io/pymilvus/blob/master/_autodocs/api-reference/milvus-client-admin.md) accepts `texts` and `analyzer_params`; [official client reference](https://github.com/milvus-io/pymilvus/blob/master/_autodocs/api-reference/milvus-client.md) defines `upsert(collection_name, data)` and search filtering. The isolated Standalone probe now exercises these alongside dense/BM25/RRF.
- MinIO distribution issue: the [official archived MinIO source repository](https://github.com/minio/minio) now describes source-only community distribution and Docker builds from source; the [Milvus issue](https://github.com/milvus-io/milvus/issues/53430) documents the removed Docker Hub image. The pinned 2024-05-28 source tag was downloaded and SHA-256 checked before local image construction, retaining the original MinIO component rather than changing object stores.

No credential values were queried or recorded.

Task 2 configuration check: [Pydantic Settings official documentation](https://github.com/pydantic/pydantic-settings/blob/main/docs/index.md) confirms `BaseSettings` environment overrides and `SettingsConfigDict(env_file='.env', env_file_encoding='utf-8')`; its [configuration reference](https://github.com/pydantic/pydantic-settings/blob/main/_autodocs/configuration.md) confirms defaults are validated. The new rerank and recall fields use the existing `Settings` pattern and keep the Lite default until the planned Task 14 migration.

Task 3 Milvus client check: [PyMilvus client reference](https://github.com/milvus-io/pymilvus/blob/master/_autodocs/api-reference/milvus-client.md) confirms `create_schema`, `create_collection(schema, index_params)`, `describe_collection`, `list_indexes`, and `describe_index`. The [ranker reference](https://github.com/milvus-io/pymilvus/blob/master/_autodocs/api-reference/rankers.md) confirms `AnnSearchRequest` supports a filter expression and `RRFRanker`. Actual behavior, including COSINE score orientation and idempotent schema validation, was checked against the local Standalone in `tests/test_milvus_hybrid.py`.

Task 4 persistence check: [PyMilvus `upsert` reference](https://github.com/milvus-io/pymilvus/blob/master/_autodocs/api-reference/milvus-client.md) documents the `upsert_count` result; the [client admin `flush` reference](https://github.com/milvus-io/pymilvus/blob/master/_autodocs/api-reference/milvus-client-admin.md) says `flush(collection_name)` writes pending data to persistent storage. The source Plan marks MySQL rows done before calling `flush`; the implementation flushes each hybrid batch first and only then marks its rows done, so failed persistence can be retried by primary key.

Task 5 rerank check: [SiliconFlow official API](https://docs.siliconflow.cn/docs/api/rerank-post) confirms `POST /v1/rerank`, `BAAI/bge-reranker-v2-m3`, `query`, `documents`, `top_n`, and `results[].index/relevance_score`. [HTTPX official docs](https://github.com/encode/httpx/blob/master/docs/api.md) confirm `AsyncClient.post`, and its [quickstart](https://github.com/encode/httpx/blob/master/docs/quickstart.md) covers `raise_for_status`. The implementation uses optional `RERANK_API_KEY` with `SILICONFLOW_API_KEY` fallback, never logs either key, and the live three-document probe selected the warranty answer at Top-1.

Task 6 query understanding check: [LangChain Python docs](https://docs.langchain.com/oss/python/integrations/chat/perplexity) show `ChatPromptTemplate.from_messages` and prompt-to-model chaining; its [structured output example](https://docs.langchain.com/oss/python/integrations/chat/openrouter) shows Pydantic schema binding. [Pydantic field docs](https://github.com/pydantic/pydantic/blob/main/docs/concepts/fields.md) cover `Field(default_factory=list)`. The installed `glm-5.2` was then exercised with the repository's configured `json_mode`, returning five flat `standard`/`expanded` results accepted by the labeled set.
